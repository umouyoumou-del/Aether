# 五行 (Aether) 实现原理

五行的编译器用 Go 编写（编译器约 2 万行、运行时约 6 千行），把 `.ae` 源码翻译成 Go 代码，再调用 `go build` 生成原生可执行文件。

```
            ┌──────────┐   ┌──────────┐   ┌────────────┐   ┌──────────┐   ┌──────────┐
.ae 源码 ──▶│ 词法分析  │──▶│ 语法分析  │──▶│  类型检查    │──▶│ 代码生成  │──▶│ go build │──▶ 可执行文件
            └──────────┘   └──────────┘   └────────────┘   └──────────┘   └──────────┘
            lexer.go       parser.go      check*.go         gen*.go        driver.go
```

## 1. 词法分析（lexer.go）

- 在每行开头比较缩进字符串，产生 `INDENT` / `DEDENT` 记号；括号内部忽略换行；
- 下一个非空行以 `.` 或 `?.` 开头时不产生 `NEWLINE`，从而支持跨行的链式调用；
- f-字符串在词法阶段被拆成“字面文本”和“表达式源码”两类片段，表达式片段随后由一个子语法分析器解析，并保留原始的行列号；
- `match`、`case`、`select`、`prop` 等是软关键字，由语法分析器根据上下文判断。

## 2. 语法分析（parser.go）

手写的递归下降分析器，基于预先切分好的记号数组，因此可以向前查看任意多个记号（例如判断 `(a, b) => ...` 是否为 lambda、`match x:` 是否为 match 语句）。出错后会跳到下一条语句继续分析，一次报告多个错误。

## 3. 类型检查（check*.go）

分为几个阶段：

1. **收集**（check.go）：按依赖顺序（prelude 最先）收集每个模块的顶层声明，建立模块作用域；prelude 的公开名字进入全局作用域。
2. **解析声明**（check_decl.go）：类型参数与约束、基类与接口、字段、方法签名、属性、枚举成员、扩展块；检查继承环、覆盖签名、抽象方法、声明的接口是否被实现；计算构造函数签名。
3. **字段默认值与 `__init__`**：先检查所有 `__init__`，以便从 `self.x = 值` 推断字段类型。
4. **模块顶层代码**，然后是**所有函数体**。
5. **结构体可变方法**：求出结构体中会修改 `self` 的方法（包括间接调用的），再检查是否在临时值上调用了它们、是否把结构体当作要求这些方法的接口使用。

检查表达式采用“双向”方式：`expr(e, want)` 带着期望类型检查表达式，这样空列表、数字字面量、lambda 参数都能从上下文获得类型；需要隐式转换的地方（整数拓宽、包装为可空、转为接口、转为迭代器……）会在 AST 中插入 `ConvExpr` 节点，代码生成时据此生成转换代码。

泛型调用通过**合一**推断类型实参：先处理普通实参，再处理数字字面量，最后带着部分已知的期望类型检查 lambda（这样 `xs.map(x => x * 2)` 能推断出 `U = int`），仍未确定的类型参数再用期望的返回类型推断。

### 流分析

检查语句的同时维护一个“流状态”：

- **确定赋值**：哪些局部变量一定已经被赋值（分支汇合时取交集，循环体中的赋值在循环之后不算）；
- **窄化**：`x != null`、`x is Dog`、`if x:` 等条件让变量在分支中获得更具体的类型；`and`、`or`、`not`、提前 `return` 都会传递窄化信息；对变量赋值会取消窄化；循环开始前会取消循环体中被赋值的变量的窄化；
- **死代码**：`return`、`raise`、`break`、`continue` 之后的状态是“不可达”，用于判断“函数缺少 return”和给出“这行代码永远不会执行”的警告；
- **赋值表达式**：`:=` 出现在 `and`/`or` 右侧、条件表达式分支、`??` 右侧或推导式中时只在部分路径上执行。检查器记录每次 `:=`，检查完这部分表达式后撤销它的效果（新变量不再算已赋值、被赋值的变量取消窄化），并把“已赋值”作为一种特殊的窄化信息放进确实执行了它的分支（`and` 为真、`or` 为假），与 `x != null` 的窄化一起沿着条件传递。

`match` 会检查枚举成员、布尔值、列表长度是否被完全覆盖。

## 4. 代码生成（gen*.go）

生成的代码与五行源码的对应关系：

| 五行 | Go |
|---|---|
| `int` `float` `str` `bool` `char` | `int` `float64` `string` `bool` `rt.Char` |
| `list[T]` `dict[K, V]` `set[T]` | `*rt.List[T]` `*rt.Dict[K, V]`（保序）`*rt.Set[T]` |
| `(A, B)` | `rt.T2[A, B]`（值类型） |
| `T?` | `rt.Opt[T]{V, Ok}` |
| `fn(A) -> R` | `func(A) R` |
| `iter[T]` | `func(func(T) bool)`，即 Go 1.23 的 range-over-func 迭代器 |
| `chan[T]` | `chan T` |
| 生成器函数 | 返回一个迭代器函数，`yield x` 变成 `if !yield(x) { return }` |
| `async def` | `rt.Async(func() T { ... })`，`await` 变成 `.Await()` |
| `go f(x)` | 参数先求值，再 `go func() { defer rt.GoGuard(); f(...) }()` |
| `try/except/finally` | 立即调用的闭包 + `defer` + `recover()` |
| `struct` | Go 结构体（值类型）；修改 `self` 的方法使用指针接收者 |
| 简单枚举 | `type E int` 和一组常量 |
| 带数据的枚举 | 一个 Go 接口 + 每个成员一个结构体 |
| 模块级变量 | Go 包级变量；每个模块的顶层代码是一个初始化函数 |
| `extend` 中的方法与属性 | 普通的 Go 函数，接收者是第一个参数；接口的扩展以接口类型接收 `self`，调用时 Go 自动把实现类型的值转换为接口 |
| `(x := v)` | `func() T { x = v; return x }()`（局部变量都提升到函数开头声明） |
| `first, *rest = xs` | `rt.CheckLenMin` 检查长度，`rt.ListRest` 取出剩余元素组成的新列表 |
| `key=len`、`map(int, xs)` 等 | 检查器包装为等价的 lambda：`(ꞏa0) => len(ꞏa0)` |
| 定义了 `__repr__` 的类型 | 额外生成 `Reprꞏ()`（`rt.Repr` 与容器的显示使用它）；没有 `__str__` 时 `String()` 也调用它 |
| 定义了 `__lt__` 的类型 | 额外生成导出方法 `Lessꞏ`（含 `__lt__` 的接口也要求它），运行时库的排序、求最值函数通过约束 `rt.Lesser[T]` 调用它；还生成 `Cmpꞏ(any) int`，`rt.Compare` 用它比较元组中的元素和 `key` 函数的返回值 |

### 类与虚方法

Go 没有继承。五行的做法是：

- 每个类生成一个 Go 结构体，子类**嵌入**父类结构体，从而继承字段；
- 有子类（或抽象）的类额外生成一个 Go 接口 `XꞏI`，包含它的所有方法和一个返回 `*X` 的访问方法；类型为该类的变量在 Go 中就是这个接口，因此方法调用是动态分派的，字段访问通过访问方法进行；
- 没有子类的类直接用指针 `*X` 表示，方法调用是静态的、可以被 Go 内联；
- 对每个**具体类**，编译器为它可见的每个方法（包括继承来的）都生成一份**以该类为接收者的副本**。这样，父类方法中的 `self.area()` 在子类的副本里会直接调用子类的实现——这就是虚方法分派。`super().m()` 调用的是为当前类生成的“基类版本”的副本。

### 控制流穿过 try

`try` 的主体在闭包中执行，所以其中的 `return`、`break`、`continue` 不能直接写成 Go 的同名语句。生成的代码会把它们记录在函数级变量 `ꞏflow`（以及返回值 `ꞏret`）中并从闭包返回，闭包外再根据 `ꞏflow` 执行真正的 `return`/`break`/`continue`；嵌套多层 `try` 时逐层传递。

### 命名

五行的标识符中不允许出现字符 `ꞏ`（U+A78F），编译器生成的所有辅助名字都包含它（如 `Circleꞏnew`、`ShapeꞏI`、`ꞏflow`），因此永远不会与用户的名字冲突。与 Go 关键字或预声明名字冲突的用户名字会加上后缀 `ꞏ`。

### 行号映射

每条语句之前都会输出 `//line 文件.ae:行号` 指令。Go 编译器会据此记录源码位置，所以运行时的调用栈直接指向 `.ae` 文件。运行时库在打印回溯时只保留 `.ae` 文件中的帧，并把 Go 函数名还原为五行的名字（例如 `(*Account).withdraw` → `Account.withdraw`），再读取源文件显示对应的代码行。

### 常量折叠

Go 会以任意精度计算常量表达式（`0.1 + 0.2` 在 Go 中恰好等于 `0.3`），这与运行时的浮点运算不同。为保持与 Python 相同的结果，两侧都是常量的算术运算会用 `rt.Val(...)` 包一层，迫使 Go 在运行时（按 IEEE 754）计算。

## 5. 运行时库（assets/rt）

运行时是一个普通的 Go 包，嵌入在 `aether` 可执行文件中，构建时复制到生成程序的目录：

- `list.go` `dict.go` `set.go`：容器。字典是“哈希表 + 插入顺序数组”，删除时留下墓碑，墓碑过多时压缩；
- `less.go`：按用户定义的 `__lt__` 排序（稳定）与求最值；
- `str.go`：`str()`/`repr()`、Python 风格的浮点数输出、f-字符串格式说明、按字符下标访问（对最近使用的长字符串缓存字符数组，避免 `for i in range(len(s)): s[i]` 变成平方复杂度）；
- `exc.go`：异常、运行时错误分类（把 Go 的 `index out of range` 等转换为 `IndexError`）、回溯格式化；
- `task.go`：`Task`、通道辅助函数、同步原语；
- `file.go` `misc.go`：文件、`os`、`time`、`random` 等标准库的实现；`rtjson/` `rtre/` `rthttp/` `rtenc/`（base64、hashlib）`rtcsv/` 是只在程序用到时才链接的子包，避免增大 hello world 的体积；
- `heapq`、`bisect`、`itertools`、`statistics`、`textwrap`、`datetime`、`collections` 等模块用纯五行代码编写（`assets/lib/*.ae`），只在少数地方通过 `@go` 调用运行时（例如读取当前时间）。

生成的程序启动时把三个钩子函数交给运行时，使运行时能够构造五行的异常对象（例如把 `*rt.Error{Kind: "KeyError"}` 变成 prelude 中定义的 `KeyError` 类的实例）。

标准输出带缓冲：输出到终端时每次 `print` 都会刷新，输出到文件或管道时整块写出（与 Python 相同），在 `input()`、阻塞的通道接收、程序退出、未捕获异常时自动刷新。

## 6. 构建与缓存（driver.go）

`aether run` 为每个主文件维护一个构建目录（`%LOCALAPPDATA%\aether\build\<文件名>-<哈希>`），其中有 `go.mod`、`rt/` 和生成的 `main.go`。只有内容变化的文件才会被重写；生成代码、运行时和编译器版本都没有变化时，直接复用上次的可执行文件。调用 `go build` 时设置 `GOTOOLCHAIN=local`、`GOPROXY=off`、`CGO_ENABLED=0`（不需要网络、不需要 C 编译器）；如果环境变量 `GOCACHE` 指向的目录无法创建，会改用五行自己的缓存目录。

## 7. 语言服务器（compiler/analysis.go、cmd/aether/lsp.go）

`aether lsp` 通过标准输入输出实现语言服务器协议（LSP）。每次文档变化（停顿 250 毫秒后）用编辑器中的内容重新做语法与类型检查（`compiler.Analyze`，导入的模块从磁盘读取），发布诊断；然后遍历本文件的语法树，记录每个标识符、成员名、声明的名字和类型名的位置、类型（窄化后的）、符号与定义的位置，悬停、跳转、补全都基于这份记录。有语法错误时没有类型信息，悬停和补全使用上一次成功的结果。

成员补全时，正在输入的这一行往往还不完整（例如 `print(u.名`），服务器依次尝试几种修补——去掉 “.前缀”、补齐括号、整行只保留 “.” 之前的表达式——直到能通过语法分析，再查出 “.” 之前那个表达式的类型，列出它的字段、方法、属性和适用的扩展方法。

VS Code 插件（`editors/vscode/extension.js`）为了不依赖 npm 包，直接实现了所需的那部分 JSON-RPC。

## 8. 测试

- `tests/run/*.ae`：黄金测试，比较程序的标准输出与 `.out` 文件（`UPDATE=1 go test` 重新生成）；
- `tests/errors/*.ae`：在期望出错的行末写 `# 错误: 信息片段`，测试检查编译器确实在这一行报告了包含该片段的错误；
- `examples/*.ae`：每个示例都必须能编译并正常运行。

```
cd compiler
go test .
```
