# 数学库：sym · egraph · codegen · latex

这套库用纯 Aether 代码实现，由四个模块组成：`sym`（表达式内核与符号运算）、`egraph`（相等饱和）、
`codegen`（生成原生代码）、`latex`（读入与写出 LaTeX）。它们共用同一棵表达式树，可以任意组合。

`sym` 是其中的内核。它的目标不是复刻一个通用 CAS，而是让**同一个表达式同时是可推导的、可执行的、可检查的**：它的目标不是复刻一个通用 CAS，而是让**同一个表达式同时是可推导的、可执行的、可检查的**：

```python
import sym

x = sym.var("x")
f = (x + 1) ** 2

print(sym.expand(f))                       # x^2 + 2*x + 1
print(sym.diff(f, "x"))                    # 2*x + 2
print(sym.equals(f, x ** 2 + 2 * x + 1))   # true

g = sym.compile_expr(f, ["x"])             # 预先编译成闭包树
print(g([3.0]))                            # 16.0
```

四层能力共用一棵表达式树：

| 层 | 做什么 | 关键点 |
|---|---|---|
| 表达式内核 | 构造、渲染、规范形式 | 节点带值域与可微性元数据；构造时自动折叠 |
| 重写与化简 | 合并同类项、展开、三角恒等式 | 每个和与积在构造时就归到规范形式 |
| 编译与求值 | 解释求值、编译成闭包树、数值积分 | 编译后每次调用只有函数调用与算术 |
| 代码生成 | 生成 Aether 源码，再编译成原生可执行文件 | 公共子表达式提取、强度削减、梯度同源生成 |
| LaTeX 输入输出 | 从 LaTeX 源码读入，结果写回 LaTeX | 递归下降解析、带位置的错误、Unicode 公式归一 |

## 1. 构造表达式

```python
x = sym.var("x")
y = sym.var("y")

x + y            # x + y
2 * x            # 2*x（整数与浮点都可以）
x * y            # x*y
x ** 2           # x^2
-x               # -x
x - y            # x - y
x / 2            # 0.5*x
sym.num(3.0)     # 数值常量
sym.integer(3)   # 整数常量（保持整数域）
sym.fn("sin", x) # sin(x)
```

`Expr` 重载了 `+ - * / **` 与一元负号，整数与浮点数可以混用。构造过程本身就会做常量折叠与合并同类项，所以 `x + x + x` 直接得到 `3*x`。

支持的函数：`sin` `cos` `tan` `exp` `log` `sqrt` `sinh` `cosh` `tanh` `asin` `acos` `atan` `abs`。

## 2. 化简与展开

| 函数 | 说明 |
|---|---|
| `simplify(e)` | 递归化简：常量折叠、合并同类项、去掉 0 与 1、合并同底数的幂；不做分配律 |
| `expand(e)` | 分配律展开 + 整数次幂展开 + 合并同类项，得到多项式的规范形式 |

```python
sym.expand((x + 1) ** 2)          # x^2 + 2*x + 1
sym.expand((a + b) ** 3)          # a^3 + 3*a^2*b + 3*a*b^2 + b^3
sym.expand((a + b) * (a - b))     # a^2 - b^2
```

内部表示是**规范形式**：和的各项按总次数从高到低、同次数按变量名排序，积按“数值系数 → 变量 → 函数”排序，常数项永远在最后。这保证了同一个数学对象只有一种写法，`equals` 才有意义。

规范形式还包含两条恒等式：

- 同底数幂合并：`x^2 * x^3` → `x^5`
- 平方和恒等式：`sin(x)^2 + cos(x)^2` → `1`

## 3. 求导

```python
sym.diff(x ** 3 + 2 * x, "x")        # 3*x^2 + 2
sym.diff(x * sym.fn("sin", x), "x")  # x*cos(x) + sin(x)
sym.diff(sym.fn("sin", x ** 2), "x") # 2*x*cos(x^2)
sym.diff(x / (x + 1), "x")           # 1/(x + 1)^2
```

支持和、积（一般乘积法则）、商、幂（指数为常数，或一般的 `u^v`）与上述函数的链式法则。

### 不定函数：f(x)、g(x, y) 的符号微分

`sym.ufunc(名字, [自变量…])` 表示一个**没有定义**的函数，只当作处处光滑的记号。对它求导不会报错，
也不会得到 0，而是得到偏导记号 `f_1`、`g_{12}`（下标是从 1 起的自变量序号）：

```python
f = sym.ufunc("f", [x])             # f(x)
g = sym.ufunc("g", [x, y])          # g(x, y)
sym.diff(f, "x")                    # f_1(x)
sym.diff(f, "y")                    # 0（f 不含 y）
sym.diff(g, "y")                    # g_2(x, y)
sym.diff(f * f, "x")                # 2*f_1(x)*f(x)
sym.diff(f / g, "x")                # (f_1(x)*g(x, y) - g_1(x, y)*f(x))/g(x, y)^2
sym.diff(sym.ufunc("f", [x ** 2 + y]), "x")   # 2*x*f_1(x^2 + y)     ← 链式法则
sym.diff(sym.diff(g, "x"), "y")     # g_1_2(x, y)
sym.diff(sym.diff(g, "y"), "x")     # g_1_2(x, y)   ← 混合偏导与顺序无关，是同一个节点
sym.diff(sym.diff(f, "x"), "x")     # f_1_1(x)
```

规则只有一条链式法则：`d f(u₁, …, uₙ)/dx = Σᵢ f_i(u) · duᵢ/dx`，`duᵢ/dx = 0` 的项省略；
高阶时把新指标并进已有的指标并按升序存放，所以 `g_{12}` 与 `g_{21}` 是同一个节点，`equals` 能认出它们相等。
求和、积分、极限里的莱布尼茨公式照常适用：`d/dx ∫₀ˣ f(t) dt = f(x)`。

`subs_fn(e, "f", 函数式, ["u"])` 把函数换成具体表达式，偏导记号会自动换成函数式的相应偏导
（先对函数式求导，再代入自变量；代入是捕获避免的）：

```python
sym.subs_fn(f * f + sym.diff(f, "x"), "f", x ** 3, ["x"])             # x^6 + 3*x^2
sym.subs_fn(sym.diff(f, "x"), "f", sym.fn("exp", x), ["x"])           # exp(x)
sym.subs_fn(sym.diff(g, "x") + sym.diff(g, "y"), "g", x * sym.fn("sin", y), ["x", "y"])
                                                                     # x*cos(y) + sin(y)
```

不定函数没有定义，所以 `evaluate` 与 `compile_expr` 遇到它会明确报错，而不是偷偷当成 0。
`codegen` 则会生成对同名函数的调用：`f(x, y)` 生成 `f(x, y)`，`g_1(x, y)` 生成 `g_d1(x, y)`，由你提供定义。

在 LaTeX 里，约定用作函数名的字母（`f g h u v w` 及大写）和希腊字母后面紧跟括号就是函数调用，
其余字母仍然是乘法（`x(x+1)` 还是 `x*(x+1)`）：

```python
latex.parse(r"f(x) + g(x, y) + \phi(t)")          # f(x) + g(x, y) + phi(t)
latex.parse(r"f'(x) + f''(x) + f'''(x)")          # f_1(x) + f_1_1(x) + f_1_1_1(x)
latex.parse(r"f^{(4)}(x) + f^{\prime\prime}(x)")  # f_1_1_1_1(x) + f_1_1(x)
latex.parse(r"f_{1,2}(x, y)")                     # f_1_2(x, y)
latex.parse(r"f^2(x)")                            # f(x)^2   ← 与 \sin^2 x 同一个惯例
latex.diff_latex(r"f(g(x))", "x")                 # f'\left(g\left(x\right)\right) \cdot g'\left(x\right)
latex.subs_fn_latex(r"f'(x) + f(x)", "f", r"\sin u", ["u"])   # \cos\left(x\right) + \sin\left(x\right)
```

写回 LaTeX 时一元函数用撇号（四阶以上写成 `f^{(4)}`），多元函数用下标 `f_{1,2}`；两种写法都能再解析回来。

**类型上的检查**：表达式带 `smooth` 标记，含 `abs` 的表达式不是处处可微的，求导会直接报错，而不是给出一个错误的结果：

```
TypeError: 表达式 abs(x) 不是处处可微的（含有 abs 等运算），不能直接求导
```

## 4. 代入、求值与编译

| 函数 | 说明 |
|---|---|
| `subs(e, {"x": 表达式})` | 把变量替换为其它表达式，并化简 |
| `subs_fn(e, "f", 函数式, ["u", "v"])` | 把不定函数 `f` 换成具体表达式，偏导记号一起换掉 |
| `evaluate(e, {"x": 2.0})` | 按环境求值（解释执行，按节点种类分支） |
| `compile_expr(e, ["x", "y"])` | 预先编译成闭包树，返回 `fn(list[float]) -> float` |
| `vars_of(e)` | 表达式中出现的变量名（按字典序） |

```python
f = (x + y) ** 2
sym.evaluate(f, {"x": 2.0, "y": 3.0})    # 25.0

g = sym.compile_expr(f, ["x", "y"])
g([2.0, 3.0])                            # 25.0
```

`compile_expr` 是这里的“编译”：它遍历一次表达式，把每个节点变成一个闭包，闭包只捕获子闭包与常量。之后每次求值只剩函数调用与算术，不需要在每个节点上判断种类、也不需要查字典取变量值——与“解释执行”相比这是数量级的差别。这与 SymPy 的 `lambdify` 是同一思路，只是闭包树由 Aether 自己的原生代码执行。

也可以拿编译后的表达式做数值积分：

```python
import math
q = sym.compile_expr(x ** 2, ["x"])
sym.integrate_numeric(q, 0.0, 1.0, 1000)   # 0.3333333333333333
```

## 5. 恒等检查

```python
sym.equals((a + b) ** 2, a ** 2 + 2*a*b + b ** 2)          # true
sym.equals(sym.fn("sin", x) ** 2 + sym.fn("cos", x) ** 2, sym.num(1.0))  # true
sym.equals(x + 1, x + 2)                                   # false
sym.difference((x + 1) ** 2, x ** 2 + 2*x + 1)             # 0（诊断用）
```

`equals` 把两侧的差展开成规范形式，检查是否恒为 0。对多项式与含有上述恒等式的表达式是完备的；对一般的超越恒等式（例如 `sin(2x) = 2*sin(x)*cos(x)`）不保证能判定——它不做任意重写搜索。

## 6. e-graph：相等饱和

`sym` 的规范形式构造器是**快速路径**：每一步都维持一种写法，代价是只能做能直接归一的变换。
`egraph` 是**搜索路径**：把“哪些表达式相等”记成并查集，所有重写规则只添加等式、不丢弃写法，
反复饱和之后再按节点代价挑一个最小的代表。

```python
import egraph

egraph.prove_equal(x * (y + z), x * y + x * z)                    # true
egraph.prove_equal((a + b) ** 2, a ** 2 + 2*a*b + b ** 2)         # true
egraph.simplify(x * y + x * z)                                    # x*(y + z)
```

| 函数 | 说明 |
|---|---|
| `prove_equal(a, b, iterations=40)` | 把两侧放进同一张图，饱和后看是否落在同一个 eclass |
| `prove_with_graph(a, b, iterations=40) -> (bool, EGraph)` | 同上，同时返回图（可看 `report()`） |
| `simplify(e, iterations=40)` | 饱和后按代价提取最小的写法 |
| `simplify_with_graph(e, iterations=40) -> (Expr, EGraph)` | 同上，同时返回图 |
| `EGraph.add(e)` `saturate(iterations)` `extract(cid)` `report()` | 手动控制的底层接口 |

用到的重写规则（都是局部等式，没有“展开”这种整体步骤）：

| 规则 | 等式 |
|---|---|
| 结合律 | `(a+b)+c = a+(b+c)`（摊平成 n 元节点） |
| 交换律 | `a+b = b+a`（子类按编号排序） |
| 分配律 | `a*(b+c) = a*b + a*c` |
| 提取公因式 | `a*b + a*c = a*(b+c)`（分配律的逆方向） |
| 常量折叠 | 数值项先算，`0` 与 `1` 消掉 |
| 合并同类项 | `a + a = 2a`、`x * x = x^2` |
| 相反项相消 | `x + (-x) = 0` |
| 幂 | `x^0 = 1`、`x^1 = x`、`x^n`（小整数）展开成乘法 |

`(a+b)^2` 的证明过程就是这些规则自己撞出来的：

```
pow(a+b, 2) → (a+b)*(a+b) → a*a + a*b + b*a + b*b → a^2 + 2*a*b + b^2
```

**提取**在饱和后的图上按“节点数”做最小代价搜索，所以 `simplify` 挑的是**最短**的等价写法，而不是
最“展开”的：`simplify((a+b)^2)` 仍然是 `(a + b)^2`，因为它比 `a^2 + 2*a*b + b^2` 少两个节点。
想要展开形式用 `sym.expand`；想要因式分解形式用 `egraph.simplify`。

**代价与上限**（同一台机器，`a+b` 的 n 次方）：n=2 约 1ms、n=3 约 22ms、n=4 约 0.8s。
饱和是指数增长的，`EGraph` 的节点上限是 40000；`saturate` 返回是否在迭代上限内达到饱和，
`report()` 给出「轮数 / 节点数 / 是否饱和」。没饱和不代表结论错误，只是可能没证出来。

## 7. 表达式 → Aether 源码 → 原生代码

前面三条路都是「在本进程里算」。`codegen` 走的是第四条：把表达式**写成 Aether 源码**，
再交给 Aether 编译器变成原生的单文件可执行程序。这样算出来的数不再是 Aether 运行时的解释结果，
而是机器码的结果，并且可以脱离符号库单独部署。

三种求值方式的区别：

| 方式 | 每次调用的开销 | 能否脱离本进程 |
|---|---|---|
| `sym.evaluate(e, env)` | 每个节点判断一次种类、查一次字典 | 否 |
| `sym.compile_expr(e, vars)` | 只剩间接函数调用与算术（闭包树） | 否 |
| `codegen` | 直接是内联的算术与 `math.*` 调用 | 是，编译成独立可执行文件 |

```python
import codegen

print(codegen.to_module(f, ["x", "y"], "f"))   # 看生成的源码
exe = codegen.compile_native(f, ["x", "y"])    # 编译成原生可执行文件，返回路径
codegen.run_native(exe, [0.3, 1.2])            # [值, ∂f/∂x, ∂f/∂y]
codegen.verify(f, ["x", "y"], [[0.3, 1.2]])    # 端到端校验，返回最大相对误差
```

`f = exp(sin(x*y)) * sin(x*y) + (x + 1)^2` 生成出来的源码是：

```python
def f(x: float, y: float) -> float:
    _t0 = x * y
    _t1 = math.sin(_t0)
    return (x + 1.0) * (x + 1.0) + math.exp(_t1) * _t1
```

生成器做了三件事：

**1. 公共子表达式提取。** `sin(x*y)` 在这里出现两次（一次在 `exp` 里，一次在乘积里），
按结构签名统计出现次数，出现两次以上且省得比一次赋值多，就提成 `_t1`。子表达式按后序生成，
所以依赖关系天然满足。

**2. 强度削减。** `x^2` 写成 `x * x`，`x^3` 写成 `x * x * x`，`x^0.5` 写成 `math.sqrt(x)`，
`x^-1` 写成 `1.0 / x`。`math.pow` 比一次乘法贵一个数量级，而平方只多写一遍底数——只要底数里
没有函数调用，就宁可多写一遍。上面例子里 `(x + 1)^2` 因此是 `(x + 1.0) * (x + 1.0)` 而不是
`math.pow(x + 1.0, 2.0)`，实测快 30%。

**3. 梯度一起生成。** `to_module` 默认给每个变量再生成一个 `f_dx`，来源是 `sym.diff`。
符号推导和原生执行走的是同一棵树：`verify` 会逐点比较原生程序与 `sym.evaluate` 的结果，
包括所有偏导，所以「符号求导对不对」这件事有了机器可检的答案，而不是靠人肉核对公式。

| 函数 | 说明 |
|---|---|
| `expr_code(e)` | 一行 Aether 表达式文本（不做 CSE，用于贴进已有代码） |
| `to_function(e, vars, name)` | 一个函数定义 |
| `to_module(e, vars, name, with_grad=true)` | 函数 + 各偏导函数（只有 `import math`） |
| `to_program(e, vars, name, with_grad=true)` | 再加快捷主程序：从 `argv` 取值，按行打印值与偏导 |
| `to_bench_program(e, vars, name, iters)` | 基准程序：循环 `iters` 次，打印累加值与每次的纳秒数 |
| `compile_native(e, vars, name="f", workdir=null)` | 写盘 + 调编译器，返回可执行文件路径 |
| `build(source, path, out, cli=null)` | 只负责写盘与编译 |
| `run_native(exe, xs)` | 运行原生程序并把输出解析成浮点列表 |
| `verify(e, vars, points)` | 端到端校验，返回最大相对误差 |
| `bench_native(e, vars, xs, iters)` | 返回 `(纳秒/次, 累加值)` |
| `aether_cli()` | 找编译器：环境变量 `AETHER`，其次是 PATH 上的 `aether` |

编译这一步需要本机的 Aether 编译器（它自己再调用 Go 工具链，和 `aether build` 一样）：

```
AETHER=bin/aether.exe aether run examples/codegen_demo.ae
```

同一台机器上，上面那个 `f`（2 个变量、1 次 sin、1 次 exp、若干乘加）的实测：

| 方式 | 每次调用 |
|---|---|
| 原生可执行文件 | 约 28 ns |
| 闭包树 `compile_expr` | 约 106 ns |
| 解释求值 `evaluate` | 约 153 ns |

三者的累加值逐位相同（`verify` 报的相对误差是 `0.000e+00`）。差距来自两处：
闭包树每次调用要构造参数列表、走间接调用；解释求值还要按节点种类分支、按键查字典。
原生代码没有这两层，剩下的只是算术本身。

**能生成什么代码**：只支持浮点标量与 `math` 里的函数，也就是 `sym` 能表示的那一档。
不做循环展开、向量化、多线程，也不做跨函数的公共子表达式共享——每个函数各自优化。
这些是后续可做的工作，不是当前的承诺。

## 8. 读写 LaTeX

前面各节都是「用代码写表达式」。但实际工作里公式往往已经在论文或笔记里了，`latex` 模块负责两个方向的翻译：

```
LaTeX 源码 --parse--> sym.Expr --(sym / egraph / codegen)--> sym.Expr --to_latex--> LaTeX 源码
```

```python
import latex

f = latex.parse(r"\frac{1}{\sqrt{2\pi}\,\sigma}\exp\left(-\frac{(x-\mu)^2}{2\sigma^2}\right)")
latex.diff_latex(r"\exp\left(-\frac{x^2}{2}\right)", "x")        # -x \, \exp\left(-0.5x^{2}\right)
latex.prove_equal_latex(r"(a+b)^3", r"a^3 + 3a^2b + 3ab^2 + b^3")   # true
latex.evaluate_latex(r"\pi r^2", {"r": 2.0, "pi": 3.141592653589793})  # 12.566…
```

| 函数 | 说明 |
|---|---|
| `parse(text) -> Expr` | 解析单行公式；自动去掉 `$…$`、`$$…$$`、`\[…\]`、`\(…\)` |
| `parse_equation(text) -> (Expr, Expr)` | 按最外层的等号切成两侧 |
| `to_latex(e, outer=0) -> str` | 渲染回 LaTeX |
| `simplify_latex(text)` `expand_latex(text)` `diff_latex(text, x)` | 解析 + 运算 + 渲染，一步到位 |
| `subs_latex(text, {"x": "y+1"}) -> str` | 代入的值也是 LaTeX |
| `evaluate_latex(text, env) -> float` | 按环境求值 |
| `equals_latex(a, b) -> bool` | 两侧化成同一规范形式后比较 |
| `prove_equal_latex(a, b, iterations=40) -> bool` | 用 e-graph 饱和证明恒等（比 `equals_latex` 更强） |
| `LatexError(message, pos)` | 解析错误；`pos` 是出错位置（字符下标） |

支持的写法：四则（`+ - * /` 与 `\cdot \times \div`）、隐式乘法（`2x`、`(a+b)(a-b)`、`2\sqrt{3}`）、
幂与下标（`x^2`、`x_i`、`x_{i+1}`）、`\frac`/`\dfrac`/`\tfrac`、`\sqrt[n]{…}`、`|x|` 与 `\left|…\right|`、
`\left(…\right)` 等可变大小括号、希腊字母、`\sin \cos \tan \arcsin \arccos \arctan \sinh \cosh \tanh \exp \ln \log`、
以及 `\mathrm{…}`/`\operatorname{…}` 命名的多字母变量。

几个按 LaTeX 惯例处理的语义：

- `\sin^2 x` 是 `(sin x)^2`，`\sin x^2` 是 `sin(x^2)`，`\sin 2x` 是 `sin(2x)`，`\sin x \cos x` 是乘积
- `ab^2` 是 `a*b^2`：一个字母就是一个变量，幂只作用于紧邻的那个因子
- `\frac{1}{2}` 归一成 `0.5`——`sym` 的数字只有 `float`，没有有理数；要保留分数得等以后加有理数类型
- `\pi` 与 `e` 都是**符号变量**而不是数值常量。这样 `diff` 自然把它们当常数，求值时由 `env` 提供
  `{"pi": 3.141592653589793}`，而 `\sin(\pi/2)` 这类需要常量推理的化简暂时做不了
- 从 PDF 或网页复制的 Unicode 公式（`πr²`、`x³ − 2x`、`√(x+1)`、`×`、`·`）会先归一成等价命令再解析

**错误处理**：解析器不猜意图。不认识的命令、没闭合的括号、空的 `\frac{}` 参数，以及 `\sum`/`\int`/`\partial`
这类暂不支持的记号，都会抛 `LatexError`，并给出位置与附近原文：

```python
try:
    latex.parse(r"\frac{\partial f}{\partial x}")
except latex.LatexError as e:
    print(e.message, e.pos)   # 暂不支持偏导记号…（位置 6）
```

**不支持的**：`\overline` 一类修饰命令、`\begin{aligned}` 里的对齐换行（`&` 与 `\\` 只认
`matrix`/`cases`/`array` 这类环境），以及所有依赖排版上下文的命令。求和、连乘、极限、积分、矩阵、
分段函数已经在第 9 节说明。要处理整页论文，应该在更上层先做公式切分，再逐条交给 `parse`。

**为什么自己写解析器？** 需要的不是「LaTeX 转成一棵树」，而是**带位置的错误**与**直接落到 `sym` 规范形式**这两件事。
现成工具（如 LaTeX→MathML）给出的是另一套树，还要再写一遍语义映射，而且位置信息通常已经丢了。
手写的递归下降只有九百多行（含注释与渲染），换来的是一眼能看懂的语义和能指到具体字符的报错。

## 9. 求和、连乘、极限、积分、矩阵、分段

前面各节的表达式只有「值」这一种含义。`\sum`、`\int`、`\lim`、`\begin{cases}` 不一样：它们在**一个名字上绑定了变量**。`\sum_{k=1}^{n} k x` 里的 `x` 是自由的，`k` 不是；对 `x` 求导该进到求和号里，对 `k` 求导则整个式子与 `k` 无关。

`sym` 里这类节点显式记下绑定关系（`name` 是被绑定的变量），`calc` 负责把它们算出来：

| 节点 | 构造 | kids | 含义 |
|---|---|---|---|
| `sum` | `sym.sum_expr(k, lo, hi, body)` | `[lo, hi, body]` | Σ |
| `prod` | `sym.prod_expr(k, lo, hi, body)` | `[lo, hi, body]` | ∏ |
| `lim` | `sym.lim_expr(x, to, body, dir)` | `[to, body]` | `dir`：-1 左、0 双侧、1 右 |
| `int` | `sym.integral(x, lo, hi, body)` / `sym.indefinite(x, body)` | `[lo, hi, body]` / `[body]` | 定/不定积分 |
| `matrix` | `sym.matrix([[a, b], [c, d]])` | `[行数, 列数, 元素…]` | 行优先展开 |
| `cases` | `sym.cases([(cond, val), …], default)` | `[cond1, val1, …, default]` | 分段函数 |
| `rel` | `sym.rel("<=", a, b)` | `[a, b]` | 比较，`cases` 的条件用它 |

绑定关系一旦显式化，前面所有操作就必须都对：

- `simplify` / `expand` 递归进主体，`_key` 把绑定的名字也算进规范键（否则 `Σ_k` 与 `Σ_j` 会撞车）
- `subs` 是**捕获避免**的：`Σ_{k=1}^{n} x k` 代入 `x = k` 得到 `Σ_{k_1=1}^{n} k k_1`，哑变量先改名，不会把外面的 `k` 吞进去
- `vars_of` 不把哑变量算成自由变量（`Σ_{k=1}^{n} x k` 的自由变量是 `[n, x]`）
- `diff` 的规则：和的导数 = 导数的和；积用对数求导 `d(∏f) = ∏f · Σ f'/f`；定积分用莱布尼茨公式
  `d/dx ∫_{a(x)}^{b(x)} f dt = f(b)b' - f(a)a' + ∫ f_x dt`；不定积分满足 `d/dx ∫f dx = f`
- `evaluate` 逐项算（上下界必须是整数，项数上限 200 万）；`compile_expr` 把有限和的上下界展开成循环

### 求和与连乘：要出闭式，不是逐项加

```python
import latex
latex.sum_latex(r"\sum_{k=1}^{n} k")                  # \frac{1}{2}n \, \left(n + 1\right)
latex.sum_latex(r"\sum_{k=1}^{n} k^2")                # \frac{1}{6}n \, \left(2n + 1\right) \cdot \left(n + 1\right)
latex.sum_latex(r"\sum_{k=1}^{n} k^6")                # \frac{1}{7}n^{7} + \frac{1}{2}n^{6} + \frac{1}{2}n^{5} - \frac{1}{6}n^{3} + \frac{1}{42}n
latex.sum_latex(r"\sum_{k=0}^{n} k 2^k")              # 2\left(n \cdot 2^{n + 1} - \left(n + 1\right) \cdot 2^{n} + 1\right)
latex.sum_latex(r"\sum_{k=0}^{\infty} k \left(\frac{1}{2}\right)^k")   # 2
latex.sum_latex(r"\sum_{k=0}^{\infty} \frac{1}{2^k}") # 2
latex.product_latex(r"\prod_{k=1}^{n} 2^k")           # 2^{\frac{1}{2}n \, \left(n + 1\right)}
```

`calc.sum` 的判定顺序（先命中先返回）：

1. 通项与哑变量无关 → `body × 项数`
2. 多项式 × 等比 `P(k) r^k`（`P` 是 1 次或 2 次）→ 用 `Σk r^k`、`Σk² r^k` 的闭式；
   `hi = ∞` 时只在 `lo = 0` 且 `|r| < 1` 下给 `c₀/(1−r) + c₁r/(1−r)² + c₂r(1+r)/(1−r)³`
3. 等比 `c·r^k`（含 `1/(c·r^k)` 这种倒数形式）→ `c(r^lo − r^{hi+1})/(1−r)`，`hi = ∞` 且 `|r| < 1` 时 → `c·r^lo/(1−r)`
4. 多项式（先 `expand` 再看次数）→ 幂和 `Σi^p` 逐项给出；`p ≤ 4` 用因式分解好的形式，
   `p ≥ 5` 用 **Faulhaber + 伯努利数**（Akiyama–Tanigawa 算法，约定 `B₁ = +1/2`），一直做到 `p = 40`
5. 上下界都是具体整数 → 逐项加（上限 2000 项）

都对不上就原样返回节点，不假装算出来。`\sum_{k=1}^{n} \frac{1}{k}` 这类没有初等闭式（调和数）就保持符号形式
——这是对的，不该硬凑一个数。

### 极限：先采样再外推，判不出就说不存在

```python
latex.limit_latex(r"\lim_{x \to 0} \frac{\sin x}{x}")                     # 1
latex.limit_latex(r"\lim_{x \to 0} \frac{1 - \cos x}{x^2}")               # 0.5
latex.limit_latex(r"\lim_{x \to 0} \frac{e^x - 1 - x}{x^2}")              # 0.5
latex.limit_latex(r"\lim_{x \to 0} \frac{\tan x - x}{x^3}")               # 0.333333333333333
latex.limit_latex(r"\lim_{x \to 1} \frac{x^3 - 1}{x^2 - 1}")              # 1.5
latex.limit_latex(r"\lim_{x \to \infty} \frac{2x + 1}{x + 3}")            # 2
latex.limit_latex(r"\lim_{x \to \infty} \left(1 + \frac{1}{x}\right)^x")  # 2.71828182846173
latex.limit_latex(r"\lim_{x \to 0^{+}} \frac{1}{x}")                      # +\infty
```

分两步：**先符号、后数值**。

符号这一步处理 `0/0` 与 `∞/∞`：检测到分子分母在 `a` 处同时为 0（或同时发散）就做**洛必达**，
`lim f/g → lim f'/g'`，最多 6 层，导数不化简到 0 就停手，避免越求越乱。

剩下的交给数值：`x → a` 时取 `h = 0.1·2^{-k}` 的采样序列，用 **Neville 外推**（按 `h` 做多项式插值再取 `h = 0`）
把 `O(h)` 误差一阶阶消掉，相邻两层吻合就停手，免得过度外推放大舍入误差；
`x → ±∞` 先换成 `t = 1/x`、`t → 0±`；`|f|` 每减半一次 `h` 就翻倍增长时判为发散，返回 `±∞`；
左右两侧的外推值不一致就抛 `CalcError`（"极限不存在"），而不是取平均糊过去。

还有一条**振荡检测**：末 6 个采样值的极差超过量级的一半、且相邻两点还在明显跳动，就判为振荡并抛错。
`\lim_{x \to 0}\sin(1/x)` 就靠这个给出"极限不存在"，而不是外推出一个没有意义的数。

`limit_latex` 返回的是字符串（可能是 `+\infty` 或 `不存在`），`calc.limit_at(e, x, to, dir)` 返回 `float`。

### 积分：表驱动 + 线性换元 + 分部积分

```python
latex.integrate_latex(r"\int x^2 + 3x \, dx")     # \frac{1}{3}x^{3} + \frac{3}{2}x^{2}
latex.integrate_latex(r"\int \frac{1}{x} \, dx")  # \ln\left(\left|x\right|\right)
latex.integrate_latex(r"\int e^{2x} \, dx")       # \frac{1}{2}\exp\left(2x\right)
latex.integrate_latex(r"\int x e^x \, dx")        # x \, \exp\left(x\right) - \exp\left(x\right)
latex.integrate_latex(r"\int \frac{1}{1 + x^2} \, dx")   # \arctan\left(x\right)
latex.definite_latex(r"\int_0^{\pi} \sin x \, dx")       # 2.0
latex.definite_latex(r"\int_0^1\int_0^1 x y \, dx \, dy")  # 0.25
```

三角幂、换元、对数这几类也都覆盖了：

```python
latex.integrate_latex(r"\int \sin^3 x \, dx")            # \frac{1}{3}\cos\left(x\right)^{3} - \cos\left(x\right)
latex.integrate_latex(r"\int \sin^2 x \cos^3 x \, dx")   # \frac{1}{5}\sin\left(x\right)^{5} + \frac{1}{3}\sin\left(x\right)^{3}
latex.integrate_latex(r"\int \cos^4 x \, dx")            # \frac{3}{8}x + \frac{1}{4}\sin\left(2x\right) + \frac{1}{32}\sin\left(4x\right)
latex.integrate_latex(r"\int x e^{x^2} \, dx")           # \frac{1}{2}\exp\left(x^{2}\right)
latex.integrate_latex(r"\int \frac{x}{1+x^2} \, dx")     # \frac{1}{2}\ln\left(\left|x^{2} + 1\right|\right)
latex.integrate_latex(r"\int x \ln x \, dx")             # \frac{1}{2}x^{2} \, \ln\left(x\right) - \frac{1}{4}x^{2}
latex.integrate_latex(r"\int \frac{1}{\sqrt{1-x^2}} \, dx")   # \arcsin\left(x\right)
latex.integrate_latex(r"\int \frac{1}{x^2+2x+5} \, dx")  # \frac{1}{2}\arctan\left(\frac{1}{4}\left(2x + 2\right)\right)
latex.definite_latex(r"\int_0^1 x \ln x \, dx")          # -0.25（瑕积分，端点是 0·ln0）
```

规则覆盖：

- 多项式（含长除法），分母为一次式、`1/(1+x²)`、`c/(c₀ − c₂x²)`、`1/√(c₀ − c₂x²)`；
  **二次不可约分式** `(n₀+n₁x)/(c₀+c₁x+c₂x²)` 拆成「对数 + 反正切」
- `x^n`、`1/(ax+b)`、`sin/cos/exp/sinh/cosh/tan/log/sqrt/atan` 的线性换元
- `x^n · exp/sin/cos` 的分部积分递推；`x^n ln x`
- **三角幂** `sin^m cos^n`：`cos` 奇次换 `S = sin u`、`sin` 奇次换 `C = cos u`（都展开成幂再积分），
  都偶且次数低时直接用倍角公式
- **一般换元**：找出内层 `u(x)`，使得 `f/du` 只通过 `u` 依赖 `x`（`x e^{x²}`、`cos x sin²x`、
  `e^{√x}/√x`、`x/(1+x²)` 都是这条规则命中的）。做法是把 `f` 与 `du` 各拆成分子/分母因子表，
  做因子级抵消，再把 `u` 抽成一个临时变量，检查剩下的表达式里还有没有 `x`

定积分先求原函数再代入上下界（所以 `∫₀¹ x² dx` 给 `0.3333333333333333` 而不是辛普森近似）；
端点取不到有限值时（如 `x ln x` 在 0）改用**单侧极限**，也就是按瑕积分处理；
原函数求不出来时才退回 `sym.evaluate` 的数值积分。

多重积分直接嵌套写：`\int_a^b\int_c^d f \, dx \, dy`。解析器把 `d` 微分记号从右往左分给各层
（最外层拿最后一个），所以 `dx` 归内层、`dy` 归外层，和 LaTeX 惯例一致。

### 矩阵与分段

```python
import calc
m = latex.parse(r"\begin{pmatrix} 1 & 2 \\ 3 & 4 \end{pmatrix}")
calc.determinant(m)                       # -2
latex.to_latex(calc.inverse(m))           # \begin{pmatrix}-2 & 1 \\ \frac{3}{2} & -\frac{1}{2}\end{pmatrix}
latex.to_latex(calc.matmul(m, calc.identity(2)))
```

`calc` 提供 `determinant`、`inverse`、`matmul`、`matadd`、`scale`、`transpose`、`trace`、`identity`。
行列式分两条路：**元素全数值**时用部分主元高斯消元（`O(n³)`，任意阶，6 阶、20 阶都行）；
**带符号**时用拉普拉斯展开（≤ 5 阶，因为符号展开是阶乘级复杂度）。逆矩阵用伴随矩阵/行列式（≤ 4 阶）。
元素本身是 `sym.Expr`，所以矩阵里放符号、放 `\frac`、放表达式都可以。

```python
f = latex.parse(r"\begin{cases} x & x \ge 0 \\ -x & x < 0 \end{cases}")
sym.evaluate(f, {"x": -4.0})    # 4.0
latex.to_latex(f)               # \begin{cases}x & x \ge 0 \\ -x & x < 0\end{cases}
```

`cases` 按顺序取第一个成立的条件，都不成立时用默认值（`\text{otherwise}` 那一行）。分段函数被标为**不可微**，
对它求导会报错——这是对的，`|x|` 在原点是不可微的，用 `sym.fn("abs", x)` 表达时也一样。

### 几条按 LaTeX 惯例处理的语义

- `\sum_{k=1}^{n} 3k + 1` 的通项只到 `+` 之前（LaTeX 的排版也是这样）。要把整个括号纳入求和，写 `\left(3k+1\right)`。
- `\prod_{k=1}^{n}`、`\sum_{k=1}^{n}` 的上下界可以任意顺序写（`\sum^n_{k=1}` 也认）。
- `\int` 缺少 `dx` 会直接报错并提示，而不是猜一个积分变量。
- `e^x` 按 `\exp(x)` 理解；`\pi` 仍是符号变量，只有在数值计算（`definite`、`limit`）时才换成 `3.14159…`。
- 矩阵环境（`pmatrix`/`bmatrix`/`vmatrix`/`matrix`/`array`）解析成同一个矩阵节点，写回统一用 `pmatrix`；
  `vmatrix` 需要行列式值时用 `calc.determinant`。
- 数字仍然只有 `float`：`1/6` 在表达式里是 `0.166666666666667`，但**写回 LaTeX 时会吸附成小分母分数**
  （`\frac{1}{6}`），所以闭式公式读起来还是对的。

## 10. 泰勒展开、偏导、解方程

前面几节都是「把一个式子化成另一个式子」。这一节是「从一个式子挖出数值信息」：
在某点附近的多项式近似、对哪个变量求了几阶导、方程的解在哪里。

### 泰勒展开

```python
import calc, latex, sym
x = sym.var("x")
calc.series(sym.fn("exp", x), "x", 0.0, 5)          # 1/120 x^5 + … + x + 1
latex.taylor_latex(r"\sin x", "x", 0.0, 7)          # -\frac{1}{5040}x^{7} + \frac{1}{120}x^{5} - \frac{1}{6}x^{3} + x
latex.taylor_latex(r"\ln x", "x", 1.0, 3)           # 1 - \left(x - 1\right)^{3} + \left(x - 1\right)^{2} - \left(x - 1\right)
latex.taylor_latex(r"\frac{1}{1-x}", "x", 0.0, 4)   # x^{4} + x^{3} + x^{2} + x + 1
```

系数是 `f^{(k)}(a)/k!`：用 `sym.diff` 反复求导，每次在 `a` 处 `evaluate`。所以：

- 只给截断多项式，**余项不写**；
- 在奇点处（`1/x` 在 0）直接抛 `CalcError`，不会偷偷给 Laurent 级数；
- 阶数上限 40 —— 40! 已经超出 `float` 的整数精度，再往上加项没有意义；
- 系数写回 LaTeX 时按连分数吸附成分数，`1/120`、`1/5040` 都能还原。

### 偏导与微分算子

`\frac{\partial}{\partial x}`、`\frac{\partial^2}{\partial x \partial y}`、`\frac{d}{dx}` 可以直接写：

```python
latex.to_latex(latex.parse(r"\frac{\partial}{\partial x} x^2 y"))                  # 2x \, y
latex.to_latex(latex.parse(r"\frac{\partial^2}{\partial x \partial y} x^2 y^3"))   # 6x \, y^{2}
latex.to_latex(latex.parse(r"\frac{\partial^2}{\partial x^2} x^3"))                # 6x
latex.to_latex(latex.parse(r"\frac{d}{dx} \sin x"))                                # \cos\left(x\right)
```

- 分子为空（`\frac{\partial}{\partial x} f`）时，算子作用于**后面那一项**：`\frac{\partial}{\partial x} x^2 y`
  是 `∂(x²y)/∂x`，遇到 `+`/`-` 就停；要作用整段请写 `\left(…\right)`。
- 分母的 `\partial x^2` 展开成对 `x` 求两次，与 `\partial x \partial x` 等价；阶数 `\partial^2` 与变量个数不一致时，
  多出来的补在第一个变量上。
- 分子里写具体表达式（`\frac{\partial (x^2y)}{\partial x}`）也一样。
- 分子里是不定函数名（`\frac{\partial f}{\partial x}`）时，`f` 读成以分母里的变量为自变量的函数 `f(x)`，
  结果是偏导记号 `f'(x)`；`\frac{\partial f}{\partial x \partial y}` 得到 `f_{1,2}(x, y)`。
  这里 `f` 的自变量就是分母里列出的变量；别处写成 `f(x, y)` 的 `f` 是二元函数，与一元的 `f(x)` 是两个不同的记号。

### 解方程

```python
x = sym.var("x")
calc.roots(sym.add(x ** 2, sym.num(-4.0)), "x")            # [-2.0, 2.0]
calc.roots(sym.add(x ** 2, sym.num(1.0)), "x")             # []（无实根）
latex.solve_latex(r"x^3 - 3x + 2 = 0", "x")                # x = -2, x = 1
latex.solve_latex(r"x^4 - 5x^2 + 4 = 0", "x")              # x = -2, x = -1, x = 1, x = 2
latex.roots_latex(r"x^2 - 5x + 6", "x")                    # [2.0, 3.0]（省掉 "= 0" 也行）
```

- 1、2 次：闭式；3 次：**Cardano**（判别式分支：单根 / 三重根 / 三角解法三个实根）；4 次：**Ferrari**
  （解 resolvent 三次方程取正根，再拆成两个二次）
- ≥ 5 次：数值 —— 用 **导数的根**把实轴切成单调段，再在每段两端判号做二分。偶数重根不改变符号，
  但它一定落在临界点上，所以不会漏
- 只返回**实根**（升序、去重），复数根不返回；判别式为负给空列表
- `calc.solve(lhs, rhs, x)` 解一般等式；`latex.roots_latex` 既能接 `"… = 0"` 也能只接左边

### 线性方程组

```python
a = sym.matrix([[sym.num(2.0), sym.num(1.0), sym.num(-1.0)],
                [sym.num(-3.0), sym.num(-1.0), sym.num(2.0)],
                [sym.num(-2.0), sym.num(1.0), sym.num(2.0)]])
b = sym.matrix([[sym.num(8.0)], [sym.num(-11.0)], [sym.num(-3.0)]])
calc.solve_linear(a, b)      # [2.0, 3.0, -1.0]
```

部分主元高斯消元 + 回代。系数带符号、或矩阵奇异（主元小于 `1e-13`）时明确报错，不返回一个看起来像解的数组。

## 12. 设计说明

**为什么用 `class` 而不是 `enum`？** 表达式是递归结构（`Expr` 含 `list[Expr]`）。Aether 的类型别名不能递归引用自己，`struct` 也不能按值包含自己，但 `class` 是引用语义，可以安全地表达递归。

**为什么有两套化简？** 规范构造器是确定性的：给定表达式，一步到位得到唯一写法，开销线性，适合日常使用。
它的局限是无法表达“换个方向看更简单”——分配律一旦反向使用就会破坏规范形式。e-graph 补上这一点：
它保留所有等价写法，用饱和搜索把等式传递开，最后按代价挑代表。两者共用同一棵 `Expr`，可以互相转换。

**为什么在构造时就化简？** 如果允许“未化简”的节点存在，任何两个写法都要在比较时临时归一，`equals` 与求导都得反复处理同一种情况。把不变量压到构造函数里（`_mk_add` / `_mk_mul` / `_mk_pow`），上层代码就只需要一种形状的输入。这与编译器里“让非法状态无法表示”的做法是同一件事。

**为什么生成源码而不是直接生成机器码？** 生成源码让 Aether 编译器（以及它背后的 Go 编译器）继续做寄存器分配、
内联、常量传播这些事，符号库只需要保证「生成的是正确且便宜的表达式」。同时生成的源码是**可读、可检查、可手改**的：
出问题时能一眼看出是哪一步写错了，而这在直接吐汇编的方案里做不到。

**值域与可微性**：`num(3)` 与 `integer(3)` 都记为整数域，整数系数的展开结果保持精确（`1e16` 以内不会出现 `1.9999999`）；含 `abs` 的表达式标记为不可微。这是把语言的类型系统用在数学对象上的一次尝试——更彻底的做法是把定义域与形状编码进静态类型，让错误在编译期就出现，那是下一步。

## 13. 当前限制

- 没有复数域、没有任意精度有理数（系数是 `float`，`1e16` 以内整数精确）。
- `equals` 只做“展开到规范形式”的比较，不做一般的重写搜索，也不做三角和差化积。
- 解方程只给**实根**（复数根不返回）；5 次以上是数值解（用导数分割 + 二分，精度约 `1e-13`），
  重根只报一个。超越方程（含 `e^x`、`\sin x`）不在 `calc.roots` 的范围内。
- 展开的整数次幂上限是 64（`MAX_EXPAND_EXPONENT`），防止 `(a+b)^100000` 这类表达式耗尽内存。
- `egraph` 只知道代数规则，没有三角函数与超越函数的恒等式（`sin^2+cos^2=1` 是 `sym` 构造器直接归一的）；
  饱和是指数增长，节点上限 40000，超过上限时返回“未饱和”，不会给出错误结论。
- `codegen` 只处理浮点标量表达式，没有向量化、循环优化与跨函数 CSE，生成的程序是单线程的。
- `latex` 只解析单行公式的常用子集：`\overline`、`\underbrace` 这类修饰命令，以及 `aligned` 里的对齐换行还不认；
  `\frac{1}{3}` 在表达式内部仍是 `float`（只有写回 LaTeX 时才吸附成分数）。
- 幂和用 Faulhaber + 伯努利数做到 `p = 40`；`Σ1/k`（调和数）、`Σ1/k^2`（`π²/6` 型）这类保持符号形式。
- 极限仍然不是符号证明：先做洛必达（最多 6 层），再做数值外推。振荡检测是**启发式**的
  （看末几个采样值的极差与跳动），构造得足够刁钻的函数仍可能骗过它；需要严格结论时应该用
  `sym` 自己推，而不是问 `calc.limit`。
- 积分是规则表 + 一层换元，不是 Risch 算法：一般换元只认「`f/du` 只通过 `u` 依赖 `x`」这一种模式，
  分母是三次以上、需要一般部分分式的有理函数做不到；椭圆积分、伽马函数这类特殊函数没有；
  三角幂都偶且次数高时要求先手动降幂。规则覆盖之外会明确报错，不返回错误结果。
- 泰勒展开没有余项估计，也不处理 Laurent 级数（奇点处直接报错）。
- 矩阵的行列式：数值任意阶，符号 ≤ 5 阶；逆矩阵 ≤ 4 阶（符号展开是阶乘级）。
- 不定函数的认定靠字母约定：只有 `f g h u v w`（及大写）和希腊字母后面紧跟括号才读成函数调用，
  `p(q+1)`、`x(x+1)` 仍是乘法。`f^{(n)}` 的阶数 `n` 必须是整数常量；`f^{-1}(x)`（反函数）不认，
  会被读成 `f(x)^{-1}`。`f'` 只对一元函数有意义，多元函数要写 `f_{1}(x, y)` 或 `\frac{\partial f}{\partial x}`。
- 不定函数只是记号：`equals` 只比较结构（`f_{12}` 与 `f_{21}` 是同一个节点，但 `f(x)` 与 `f(2x)` 无从比较）；
  `evaluate`、`compile_expr`、`calc` 的数值功能遇到它会报错，需要先 `subs_fn` 换成具体表达式。
- 尚未生成可交给 Lean 等证明器检查的证书；`equals` 给出的“两侧化为同一规范形式”是目前能做到的最强结论。

- 证书的完备性刻意受限：证书只判「四则运算 + 整数次幂 + 12 个函数当作不透明原子」下的
  多项式恒等。`sin²+cos²=1`、`x/x=1`（消去律）这类需要额外代数/三角事实的式子判不出来——
  因为校验器不假设任何东西，宁可说「验不了」也不引入未经验证的恒等式。导出时含非白名单节点
  （如 `ufunc`/`df`/`sum`/`int`）会直接拒绝，需要先用 `expand` 化到四则运算，或先 `subs_fn`。

## 15. 证书：把推导交给独立校验器

`equals` 说「两侧化为同一规范形式」，但这仍然只是 `sym` 自己的判断。要让人**不必
相信 `sym`** 也能确认一个结论，需要把推导写成证书，交给一个不共享任何代码的校验器
逐行核对。仓库 `lean/` 下就是这个校验器（Lean 4 编写，不依赖 Mathlib）。

### 15.1 为什么值得做

`expand`/`diff`/`equals` 都在同一个进程里算。如果求导的链式法则写错了，`diff` 会
理直气壮地返回一个错误结果，而 `equals` 也会「自洽地」认为它没问题——因为两边用的是
同一套（可能错误的）逻辑。证书把「结论」拆成「每一步等式变换」，交给另一套独立实现
重算，错误会在**具体哪一行**暴露出来。

### 15.2 证书长什么样

```
aethercert 1
vars x
start (pow (add (var x) (num 1)) 2)
same  (add (pow (var x) 2) (add (mul (num 2) (var x)) (num 1)))
claim (add (pow (var x) 2) (add (mul (num 2) (var x)) (num 1)))
end
```

逐行、前缀语法。`cert` 模块的 `cert_expand`/`cert_simplify`/`cert_diff`/`cert_equal`
分别产出这几种证书。

### 15.3 校验器只认一件事

把两个端点各自**独立地**规范化成多项式（排序 + 合并同类项），比较系数是否逐项相同。
它不懂 `sin`，也不需要懂：函数符号当作不透明原子，同一个 `sin(x)` 前后就是同一个值。
于是：

- **`same` 步：零假设。** 只判 `canonical 上一项 = canonical 声称项`，而
  `canonical_sound` 已证「规范化保持语义」。
- **`diff` 步：唯一的假设是那张 12 行导数表**（`sin'=cos`、`cos'=-sin` …）。
  校验器把 `deriv x 上一项` 自己算一遍，再判它与声称项恒等。换句话说，`diff` 归约成
  `same`，不额外需要微积分公理。

要审计这套系统，只需逐行看那张导数表是否与你想承认的微积分一致，其余全是机器验证的
代数变形。

### 15.4 设计取舍：只证可靠性，不证完备性

只证「规范化保持语义」（可靠性），**不证**「规范形唯一」（完备性）：

```
canonical a = canonical b  ⟹  eval a = eval b
```

所以 `norm` 不合并同类项、不排序都不影响**正确性**，只影响**能判出多少**。完备性靠
排序 + 合并同类项补上一部分（交换律、分配律、平方展开、`2x+3x=5x` 都判得出），但刻意
留缺口：`sin²+cos²=1` 判不出来（要判它就得引入三角恒等式，那就不是「零假设」了）。

一个具体的完备性细节：求导会产生 `x*0` 这类零系数项，若不剔除，`d/dx(x/2)` 算出的
`(1*2 + -(x*0))/(2*2)` 就化简不到 `1/2`。校验器的 `stripZero` 剔除零项后，这类式子
才判得出来——这同时让 `x + 0 = x` 变得可判定。

### 15.5 信任边界与精度

`sym` 的系数是 `double`。证书里的数必须精确：

- 能被 double 精确表示的数（整数、`0.5` 等）用最短往返表示导出，校验器按 IEEE-754
  精确语义解析，两侧一致。
- 超出 double 精确范围的整数（`> 2^53`）导出直接拒绝，而不是给出一份四舍五入的证书。

函数名限定在 12 个白名单内（`sin`…`acos`，不含 `sym` 支持的 `abs`），其余拒绝。
**宁可拒绝也不撒谎**：导不出来就抛错，绝不生成一份看起来对、实则改了数值的证书。

### 15.6 跑校验器

```
cd lean
export PATH="/e/Apps/elan/bin:$PATH" && export ELAN_HOME='E:/Apps/elan'
lake build certcheck
.lake/build/bin/certcheck /path/to/my.cert     # 退出码 0 通过 / 1 拒绝 / 2 用法错误
```

失败时报「第 N 行：`diff` 不成立。内核把 … 对 x 求导得 …，证书声称 …」，直接定位到
出错的推导步。`lean/AetherCert/Deriv.lean` 里那张 `dtable` 就是全部信任假设所在处。

### 15.7 让 Mathlib 做「第二见证人」

`certcheck` 证明的「成立」，本质是「在本仓库这套内核里成立」。它的可信基础是
我们自己的 `canonical`、158 行手写引理和 `Deriv.dtable`——都对，但都是同一批人
写的，万一某条引理本身写错，校验器会**自洽地错**。

要真正「独立」，就需要另一个**完全无关的实现**来核对同一件事。Mathlib 的
`ring` 策略正合适：它不认识 `canonical`，只认交换半环公理；它的导数库也不认识
我们的 `dtable`。`lean/AetherCert/Gen.lean` 里的 `cert2lean` 把证书的每一步翻成
一条 Mathlib 命题：

```
same 步  →  example (x : ℚ) : lhs = rhs := by ring
diff 步  →  example (x : ℝ) : deriv (fun t => lhs) x = rhs := by simp <;> ring
```

配套的校验工程在 `lean-mathlib/`：`lake exe cache get` 拉 Mathlib 预编译缓存后，
`lake env lean Examples.lean` 编译通过，即表示每一步都被 Mathlib 认可；任一行报错
就精确指向被改坏的那一步——与 `certcheck` 的行为一致，只是换了个更值得信任的裁判。

一个具体例子。证书 `t1` 声称 `(x+1)² = x²+2x+1`，`cert2lean` 生成：

```lean
import Mathlib
example (x : ℚ) : ((x + (1 : ℚ)) ^ 2) = (((x ^ 2) + ((2 : ℚ) * x)) + (1 : ℚ)) := by
  ring
```

这条 `ring` 若编译通过，就是 Mathlib 独立给出的「成立」签名——它压根不知道
Aether 的存在。

要点：

- **`cert2lean` 不依赖 Mathlib**（本包编译不需要它），只有它生成的 `.lean` 才
  `import Mathlib`。所以没装 Mathlib 的机器也能跑翻译、检查生成的源码。
- **能力边界一致**：证书表达得了的（四则、整数幂、12 个初等函数）Mathlib 都能验；
  证书表达不了的（`sin²+cos²=1`、`x/x=1`）这里也验不了——两套实现的强项与短板
  是对齐的，不会出现「证书证出了 Mathlib 证不出的东西」这种可疑情况。
- **代价**：Mathlib 是重型依赖（全量 olean 约十几 GB、冷编译数小时）。所以它被
  放在**独立的 `lean-mathlib/` 子工程**里，可选项，不影响本包「零依赖、
  `lake build` 几十秒」的日常使用。
